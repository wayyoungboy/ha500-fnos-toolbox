# HA500 飞牛工具箱

面向奥睿科 HA500 的 fnOS 原生硬件工具箱。一个 Go 服务同时提供五盘位蓝色硬盘灯、每路风扇独立策略、软件控制验证和有界运行日志，不需要 Python，也不依赖 CoolerControl 常驻进程。

当前测试版：`v0.2.0`。应用界面的风扇状态栏和页脚会显示实际运行版本。

> [!WARNING]
> 当前为测试阶段，只在一台奥睿科 HA500 上验证。硬件控制存在风扇停转、过热、数据损坏或设备异常的风险；使用者应自行确认型号、做好数据备份并承担风险。本项目不提供任何明示或暗示担保。

## 已实现

- ASM1166 控制器本地端口扫描，避免其他 SATA 控制器导致 `ataN` 整体偏移。
- 五个物理盘位可从 ASM1166 的 1～6 号端口中任选五个且不重复映射。
- 自动灯光与手动核对模式；蓝色盘位灯为低电平点亮。
- 只选择同时存在可写 PWM 和有效 RPM 反馈的风扇通道。
- 每路风扇独立选择仅监控、自动曲线、固定转速或全速保护；温度源可选 CPU Package 或任一块 SATA 硬盘，自动曲线会实时绘制温度、PWM、当前温度和临界温度。
- 硬盘温度使用序列号 SHA-256 指纹作为稳定身份，换线或重启导致 `/dev/sdX` 变化后仍跟踪同一块盘；界面只显示盘位、型号和派生短 ID。
- SMART 每 30 秒并行刷新一次，并使用 `smartctl -n standby,0` 避免为了读温度唤醒休眠硬盘。
- 单路软件控制验证会短时调整 PWM、观察 RPM，并始终恢复原状态。
- 温度读取失败、受控风扇异常或服务退出时，将本应用拥有的风扇切换到 100%。
- 原生 fnOS 管理员界面、运行日志、一键清空和自动轮转。

## 硬件与系统

首版只支持 x86_64 的奥睿科 HA500，参考硬件为 Intel N5105、ASM1166 SATA 控制器、`INT34C8:00` PCH GPIO 和 IT8613 监控芯片。

已测试环境：

- fnOS `1.2.0302`
- 内核 `6.18.18.c938-trim`
- `it87 force_id=0x8620`
- 风扇通道 FAN 2 / PWM 2 与 FAN 3 / PWM 3
- 系统自带 `/usr/sbin/smartctl 7.3`

安装包只尝试加载当前系统已有的 `it87` 模块，不包含、不下载、也不替换内核模块。模块不存在时，硬盘灯仍可使用，风扇页面会保持只读并显示驱动不可用。

## 安全模型

新安装默认只读。满足以下条件后，单路风扇才能启用写控制：

1. HA500 保守硬件指纹匹配；
2. 系统提供 `it87` 的 PWM、模式和 RPM 接口；
3. CoolerControl 与 fancontrol 等冲突服务已停止；
4. 该风扇完成软件控制验证；
5. 用户为该通道保存了非“仅监控”策略。

风扇当前为 100% 时，验证不会擅自降速；必须在界面再次确认。没有 RPM 反馈的 PWM 通道不会被接管。

## 从旧硬盘灯应用迁移

安装测试包前应先卸载 `HA500 硬盘灯`（包标识 `ha500_led`），确认旧进程、Unix Socket 和安装目录已经消失，再安装本工具箱。两个应用不得同时控制同一组 GPIO。

CoolerControl 可以保留用于初次只读验证，但只要它仍处于运行状态，本工具箱就不会验证或接管风扇。确认工具箱读取正常后，再停止并禁用 CoolerControl，逐路完成验证。

## 构建

需要 Go `1.25.12` 或更高安全修订版。构建出的应用本体为静态 Linux amd64 二进制。

```bash
make test
make stage        # 只生成并校验包目录
FNPACK=/path/to/fnpack make build
```

CI 会执行竞态测试、`go vet`、`govulncheck`、包结构/隐私检查，并使用校验过 SHA-256 的 fnpack 生成 FPK。

## 原理与来源

硬盘灯 GPIO/盘位关系来自 HA500 原厂 OpenWrt 备份的行为分析，并在实机上逐灯核对；仓库不包含原厂固件或厂商代码。磁盘识别只读取 Linux sysfs 中 ASM1166 控制器与块设备拓扑。

风扇部分来自对当前 fnOS 内核和 IT8613 的实机诊断：该芯片在当前环境中通过 `it87 force_id=0x8620` 暴露 hwmon。控制遵循 Linux hwmon 的标准含义：`pwmN` 范围 0～255，`pwmN_enable=1` 为手动 PWM。自动曲线在本应用的用户态循环中计算，不依赖芯片自动模式。

硬盘温度读取使用 fnOS 自带的 `smartctl` JSON 接口。应用只在内存中读取明文序列号并立即计算 SHA-256 指纹；风扇策略保存 `disk:<fingerprint>`，不保存设备名或明文序列号。SMART 温度不可用、硬盘离线或已保存的硬盘未找到时，引用该温度源的风扇进入 100% 失效保护。

- [Linux it87 驱动文档](https://docs.kernel.org/hwmon/it87.html)
- [Linux hwmon sysfs 接口](https://docs.kernel.org/hwmon/sysfs-interface.html)
- [详细需求与失效保护](docs/REQUIREMENTS.md)

## 隐私

状态与诊断接口不返回明文磁盘序列号、用户名、密码、私有路径、IP 地址或令牌。接口只返回不可逆序列号指纹和派生短 ID，用于在盘符变化后识别同一块盘。CI 会扫描仓库与包内文本，阻止硬编码凭据和私网地址进入发布物。
